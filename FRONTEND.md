# Frontend — Run & Safety Notes

Short guide to build and run the project's frontend(s) locally, plus git-safety notes so forks/merges stay clean.

Prerequisites
- Node.js (16+) and npm installed
- Git configured for your fork/branch

Build & serve the site (static preview)
1. Generate the site data (this writes `site/data.js`):

```powershell
node site/build.js
```

2. Serve the built `site/` folder (example uses `serve` via `npx`):

```powershell
npx serve -s site -l 3000
# open http://localhost:3000
```

Alternatively, use the repository helper script `start-frontend.ps1` from the repo root:

```powershell
.\start-frontend.ps1
```

Or open the browser automatically:

```powershell
.\start-frontend.ps1 -Open
```

3. Quick health check (PowerShell):

```powershell
Invoke-WebRequest -Uri http://localhost:3000 -Method Head -UseBasicParsing | Select-Object StatusCode, StatusDescription
```

```powershell
# then inspect the scripts in package.json and run the appropriate script, common ones:

```

If a package uses `pnpm` or `yarn`, use those instead of `npm`.

Git-safety & merge-safe workflow (READ THIS)
- Do not commit generated files that CI manages automatically. Notably:
  - `site/data.js` is generated by `node site/build.js` and handled by CI on main — avoid committing it from feature branches.
  - `catalog.json` and other generated artifacts are gitignored.
- Avoid running any repository auto-fix scripts that modify README counts or site data unless you intend to update main. CI will rebuild and fix counts on merge to `main`.
- When preparing PRs, only change source files: lesson docs (`phases/.../docs/en.md`), `code/` files, `quiz.json`, `outputs/`, or docs at repo root. Follow the repo's commit rules in `AGENTS.md`.

Troubleshooting
- Port in use: pick another port (`-l 3001`) or kill the process using the port.
- Missing `serve`: `npx` will prompt to install; you can install globally with `npm i -g serve` to avoid prompts.
- Node version mismatch: use `nvm`/`nvm-windows` to switch Node versions.
